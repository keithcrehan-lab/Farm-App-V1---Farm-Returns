# Farm Return — Overview Default Map / Farm Today Phase 1 Implementation

Date: 19 November 2026
Owner approval: **implement working prototype, review before production deployment**.

## Objective
The real Farm homepage (`src/app/(app)/today/page.tsx`) currently defaults to the Grass lens. Owner wants a **three-way map switch in this order: Overview | Grass | Soil**, Overview selected on every new Farm entry unless an explicit deep link specifies a different lens. Overview is a genuinely actionable daily operational map, with restrained field indicators plus a compact expandable Farm Today panel on the map. Preserve existing beautifully presented satellite view, field markers, weather/conditions, cattle/GPS, Grass and Soil layers. This is not a new page, full map rebuild, AI-generated action engine, or an excuse to change scientifically sourced calculations. The existing Grass screen at `/grass` is a different screen and must remain unchanged.

## Farm Today UX and data contract
1. Compact always-visible overlay **while Overview selected only**: title `Farm Today`, counts or concise summary of *genuine actionable* farm-topic items, and most important real prompt or clear state. Should be attractive and polished in existing deep-green/satellite aesthetic, not beige report cards. Don't crowd map: max 170px tall at 360px when collapsed, avoid bottom nav and lens selector.
2. Tap/expand to a scrollable panel with a maximum initially visible prioritised action list, each item showing concise real title, type, evidence/recency where available, field association only when actually linked, and one existing supported CTA. Provide clear collapse and an accessible labelled button. Can reuse existing `Sheet` and `TodayControlRoomRail` with a compact trigger and dynamic summary; adapt styling to overlay; avoid conflicting double-sheet interactions.
3. Farm-level action should be clearly labelled `Farm-wide` and **never displayed on a specific field marker** simply because its category `affectedFieldIds` has members.
4. On field map, show up to 3 unobtrusive **action labels** on mapped fields with source-backed field-specific actionable prompts. Remaining fields with genuine field-linked actions get small indicators with count or icon, but if MapHero cannot support markers without significant change, implement as a small additive presentation extension using existing marker formatting and selection, not an unrelated map rebuild. Never hide field names or cattle markers. If reliable per-field rule cannot be established safely from existing source, leave markers neutral and show action in Farm Today list with explicit source. Do NOT fake or invent tasks.
5. Two-way selection: choosing an item highlights/zooms to the mapped affected field using existing selectedFieldId / MapHero behaviour and opens its field details when appropriate; clicking marker selects same field, and panel responds to selection. Farm-wide items should route to their already-supported opportunity sheet, no arbitrary field zoom.
6. Empty state `No outstanding actions identified from available records` with honest caveat; distinct loading/unavailable states; no sample data in signed-in farm.
7. For higher-density farms, deterministic priority order from verified fields and safe stable IDs, max 3 expanded map labels on mobile, collapse clustered/remaining display. Do NOT derive new scientific severity from farm-wide priorities; display prioritisation of list only when canonical source supports it.

## Technical correctness and scope
- Preserve all existing deep links, return-to-field behaviour, selected field drawer and `MapHero` camera contract. Switching map lenses should NOT reposition the camera. Any select-an-action is an actual user intent that may fly to selected field.
- No source engine, state store, data adapter, science, calculation, API, Supabase, RLS or database migrations. Existing Grass `47 kg DM/ha` anomaly untouched.
- Reuse React, Next.js and project's components. Do not add new package, paid dependency or new UI framework. Keep refactor small: `FarmTodayPanel.tsx`, pure presentation adapter + tests if needed, modifications in `today/page.tsx`, `FarmLensControl`, `farm-spatial-lenses`, and focused tests. Avoid cross-screen regressions and duplicates.
- React hydration: calculations depending on current time must remain post-mount; do not display client-only dates on first SSR render.
- Accessibility and 360/390/430px mobile: indicator tap target, contrast, scroll, MapHero layer z-index, keep visual background/map dominant, bottom nav not obstructed, reduced motion.
